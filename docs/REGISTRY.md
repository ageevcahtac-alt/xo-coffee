## 2026-11-09 — feat: файловый снимок каталога + ретрай заказа (master напрямую, без PR)

**Что:** У витрины собственный персистентный снимок каталога в JSON-файле на
диске — Upstash Redis не используется (планы изменились: переезд с Render на
собственный VPS/Docker, внешний Redis не нужен; коммита до этого не было).
Новый `src/lib/store/catalogSnapshot.ts` (readSnapshot / writeSnapshot /
buildNextSnapshot, no-throw; путь из env `CATALOG_SNAPSHOT_PATH`, по умолчанию
`./.data/catalog-snapshot.json`; запись атомарная — уникальный tmp-файл +
rename, каталог создаётся при необходимости; битый JSON в файле = отсутствие
снимка (null), не падение). `src/lib/store/catalog.ts`: успех админки → снимок
перезаписан (active = весь фид; archived = старые active ∪ archived минус фид —
строки не удаляются: снятый в песочнице лот продаётся до конца остатков);
неудача админки → выдача из снимка (active + archived); пустой валидный снимок
= честный пустой каталог, не ошибка; сбой записи при живой админке на выдачу не
влияет (warn в лог); нет ни админки, ни снимка — прежний unavailable. Заказы:
`placeAdminOrder()` — первая попытка 10 с, при таймауте/5xx одна повторная с
таймаутом 30 с (на VPS нет ~50-с холодных стартов Render free); 4xx не
ретраятся; runOnce и неблокирующий Telegram не тронуты. Конфиг:
`CATALOG_SNAPSHOT_PATH` задокументирован в `.env.example` (prod-VPS:
/data/catalog-snapshot.json на смонтированном томе); `render.yaml` возвращён к
исходному виду — на Render снимок работает эфемерно, это ок; `/.data/`
добавлен в `.gitignore`. Зависимость @upstash/redis не добавлялась в итоге
(install → uninstall до коммита; package.json/lock без изменений).

**Почему:** отвязать каталог витрины от аптайма админки (8 с таймаут + сон
админки = недоступная витрина), хранение — файл на диске VPS.

**Проверки:** `npm test` 134/134 ✓ (11 файлов; +`store/catalogSnapshot.test.ts`,
+`store/catalog.snapshot.test.ts` — реальная FS в tmp-каталогах, без моков
модулей; placeAdminOrder-блок в `adminStoreClient.test.ts`; `catalog.test.ts`
и `orderFlow.test.ts` переведены на tmp-путь снимка) · `npm run lint` — 0
ошибок, 1 warning только в локальном `.agents/before-fix.mjs` (в git не
коммитится) · `npm run build` ✓ (роуты прежние: /, /_not-found, /api/order).
Upstash не осталось нигде: grep по `src/`, package.json, package-lock.json,
render.yaml, .env.example — пусто. Сценарии покрыты: живой фид → снимок
перезаписан и выдача из админки; 500/таймаут → выдача из снимка включая архив;
лот пропал из фида → archived и продолжает отдаваться; битый JSON снимка →
прежний unavailable без исключений (+ при живой админке файл «лечится»
следующей записью); невалидный/заблокированный путь → выдача не ломается.

**Ревью:** не запускалось (по условиям задачи).

**Риски:** низкие. Снимок — кэш, источник правды по-прежнему админка; свежесть
при падении = syncedAt последней успешной синхронизации. На Render файл
эфемерен (теряется на redeploy) — осознанно. Теоретический дубль заказа, если
таймаутнувший первый POST фактически создан админкой (ключа идемпотентности у
админки нет, контракт не меняли); runOnce это не ломает. E2E против живой
админки с реальным файлом снимка не прогонялся — покрыто тестами на реальной FS
