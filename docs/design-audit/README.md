## Ключевое ограничение окружения

Демо-каталог (`src/data/lots.json`) не содержит orderable-вариантов фасовки —
кнопка «В корзину» и цена на карточках локально отсутствуют by design
(`LotPurchaseControls` ничего не выдумывает), а seed-корзину reconciliation
(`src/lib/cartReconcile.ts`) обнуляет, потому что варианта нет в каталоге.
Поэтому **визуально пройти путь заказа (cart → checkout → payment → success)
локально невозможно без изменения кода/данных**, что вне рамок аудита.
Это само по себе зафиксировано как находка D-7 / M-8: путь заказа не
проверяем визуально ни в одной среде без подключённого Admin. Поведение
чекаута покрыто построчными аудитами P30/P31 и тестами
(`orderFlow.test.ts` 22 теста) — здесь не дублируется, верификация — кодом.

## Сводный вердикт (подробности — в offers.md)

Визуальная система P26/P27 зрелая и консистентная: тишина, кремовая база,
бордовый акцент, дисциплинированная типографика. Полный редизайн **не нужен**.
Основные разрывы — торговые механики до запуска: нет фото продукта, нет даты
обжарки, ось «способ заваривания» не видна в каталоге, путь заказа не
проходится визуально в dev-окружении, мобильная версия в целом здоровая,
но с рядом точечных дефектов эргономики.
