# Десктопный аудит — 1440×900

Скриншоты: `d01`–`d12`. Дата: 2026-11-06. Каждая находка: наблюдение →
скриншот → почему это проблема → объём (S < день, M = 1–3 дня, L > 3 дней).

## Сильные стороны (подтверждено визуально, не трогать)

- **Hero** (`d01`): за 5 секунд понятно кто/что/куда; две CTA покрывают
  оба сценария («знаю, что хочу» / «помогите выбрать»). Совпадает с P30.
- **Модалка «Паспорт зерна»** (`d04`, `d05`): CTA-подвал закреплён вне
  скролла, первым идёт ответ «почему попробовать», спеки компактной строкой,
  есть блок похожих лотов и честное объяснение «почему только в зёрнах».
- **Discovery** (`d06`–`d08`): 3 вопроса со счётчиком, «Назад», «Начать
  заново», результат с причиной рекомендации и рецептом.
- **Пустые состояния** (`d09`, `d10`): корзина даёт выход в каталог (P30),
  «Мой кофе» объясняет локальность данных и честно говорит «Пока здесь пусто».
- **Coffee Passport** (`d12`): дегустационный сценарий полный — метод,
  оценка 4 оси 1–5, заметка, история, радар профиля лота.

## Находки

### D-1. Нет фотографии продукта — правая половина Hero пустая
- **Где:** `d01` (пустой белый правый край панели), `d03` (карточки без
  изображений), `d04` (модалка без фото).
- **Проблема:** премиальность заявлена типографикой, но не подтверждена
  визуально. Бенчмарки (Onyx, Blue Bottle, Square Mile) все фото-центричны.
  На 1440px пустое поле читается как «недоделано», а не «минимализм».
- **Объём:** M (нужна съёмка/рендеры упаковки — решение и бюджет владельца).

### D-2. Витрина без кассы: цена и «В корзину» отсутствуют в демо-состоянии
- **Где:** `d03`, `d05`, `d08`, `d11` — везде «Фасовка скоро появится».
- **Проблема:** демо-каталог без orderable-вариантов, а reconciliation
  корзины обнуляет seed-позиции — путь заказа нельзя пройти визуально
  локально (подробно — README.md «Ключевое ограничение окружения»).
  До запуска это означает: визуальную приёмку cart→checkout→payment→success
  нужно делать на стейдже с подключённым Admin.
- **Объём:** S как задача аудита-приёмки (не код); данные — решение
  владельца (demo-variants или staging Admin).

### D-3. Навигация без активного состояния и без поиска
- **Где:** `d01`, `d02` — «КАТАЛОГ ПОДХОД МОЙ КОФЕ», текущий раздел не
  подсвечен; поиска нет.
- **Проблема:** на 8 лотов поиск некритичен (есть фильтры по характеру), но
  active-state — базовая обратная связь ориентации; уже зафиксировано в P28
  как неисправленное. Поиск — горизонт роста каталога.
- **Объём:** S (active-state через usePathname), M (поиск — позже).

### D-4. Второстепенные подписи каталога на грани читаемости
- **Где:** `d03` — строка «V60 · 1:16, 94°C · ГЕЙША, WASHED · ТОЛЬКО
  ЦЕЛЬНОЕ ЗЕРНО» 10px uppercase при `/60` (~3.9:1, ниже AA 4.5:1 для
  мелкого текста).
- **Проблема:** класс слабого контраста на ~30 местах задокументирован P28
  как пред-существующий и не исправленный; на светлой теме P27 читается
  хуже, чем рассчитано.
- **Объём:** S (одна правка токенов непрозрачности проходит по всем местам).

### D-5. Coffee Passport не продаёт повторно
- **Где:** `d12` — выходы «МОЙ КОФЕ / В КАТАЛОГ / ПОДОБРАТЬ СЛЕДУЮЩИЙ КОФЕ»;
  паспорт знает оценку 5/5, но не предлагает «докупить этот лот».
- **Проблема:** бенчмарк Blue Bottle строит петлю удержания сразу после
  первой покупки; у нас самый тёплый момент (оценка 4–5) не конвертируется
  в повторный заказ.
- **Объём:** M (блок «докупить» в детали паспорта, только когда лот
  orderable).

### D-6. Рекомендации «Попробовать дальше» дублируют формулировки
- **Где:** `d11` — две из трёх карточек с идентичным «Подойдёт, если
  вам нравится плотный, шоколадный кофе…».
- **Проблема:** блок выглядит шаблонным, доверие к персонализации падает.
- **Объём:** S (контент-правила подбора, не код).

### D-7. Путь заказа не визуализируем без Admin
- **Где:** README.md «Ключевое ограничение окружения»; прямое следствие D-2.
- **Проблема:** checkout/payment/success проверены только кодом (P30/P31,
  22 теста orderFlow). Это приёмлемо для кода, но экран оплаты — место,
  где визуальные дефекты (мобильная клавиатура над полями, sticky-итог)
  проявляются только вживую.
- **Объём:** M (стейдж с Admin + один прогон перед запуском).

### D-8. Микро-типографика: «№XO-100777» без пробела
- **Где:** `d11`, `d12` — «Заказ №XO-100777», «ЗАКАЗА №XO-100777».
- **Проблема:** мелочь, но на премиальном сайте типографика — продукт.
- **Объём:** S (строка формата номера).

### D-9. Результат Discovery без прямой покупки (частично следствие D-2)
- **Где:** `d08` — у рекомендации только «ОТКРЫТЬ ПАСПОРТ».
- **Проблема:** по коду (P30) «В корзину» там есть и рендерится при
  orderable-лоте; в демо нельзя показать. Проверить после подключения Admin.
- **Объём:** верификация, не работа.
