## 3. Итоговая цветовая система

Токены (`app/globals.css`) — без изменений raw-значений из P26, добавлен только семантический слой поверх:

```css
:root {
  --color-burgundy: #3b1119;
  --color-burgundy-dark: #260b10;
  --color-burgundy-light: #f3e8e9;   /* NEW — ~96%-cream тинт burgundy */
  --color-backdrop: #0f080a;
  --color-cream: #fbf8f1;
  --color-cream-dark: #f4efe6;
  --color-gold: #d4af37;
  --color-gold-dark: #a9872c;
  --color-charcoal: #222222;

  --color-background: var(--color-cream);
  --color-surface: #ffffff;
  --color-surface-accent: var(--color-burgundy-dark);
  --color-text: var(--color-charcoal);
  --color-border: rgb(34 34 34 / 0.12);
  --color-accent: var(--color-burgundy);
  --color-accent-hover: var(--color-burgundy-dark);
  --color-accent-surface: var(--color-burgundy-light);
  --color-success: #4b6355;
  --color-warning: #b8752e;
  --color-error: #b91c1c;
}
```

Принцип разделения (сознательный, не половинчатый рефакторинг): **новые системные роли** (CTA, дефолтный border, статус-цвета) идут через семантические классы (`bg-accent`, `border-border`, `text-error`, ...) — это единственное место, которое нужно будет менять при будущей рекалибровке. **Стабильные брендовые цвета** (фон секций, дозированный gold) остаются на raw-токенах (`bg-cream`, `bg-surface-accent`, `text-gold-dark`) — они не были "непоследовательными", только перегруженными, и не нуждаются в косвенности. Это прямо соответствует правилу задания "не создавай дублирующие token systems" — семантический слой не подменяет raw-токены, а дополняет их для конкретных ролей.

## 5. CTA — унификация

**Было:** Hero использовал `bg-gold`/`hover:bg-gold-dark` с `text-burgundy`; каталог, модалка лота, Discovery, Coffee Passport-страницы использовали `bg-burgundy` с `text-cream`, часть кнопок — со смешанной `border-gold` рамкой поверх burgundy-заливки.

**Стало:** единственный CTA-язык — `bg-accent text-cream hover:bg-accent-hover`, без рамки. Применено ко всем найденным основным action-кнопкам:

- `Hero.tsx` — "Смотреть каталог" (была `bg-gold`, теперь `bg-accent`)
- `Catalog.tsx` — "В корзину" на карточке (была `border-gold/40 bg-burgundy`, теперь без рамки `bg-accent`)
- `LotPassportModal.tsx` — "В корзину" в модалке
- `DiscoveryModal.tsx` — "В корзину" в результатах подбора
- `passport/MyCoffeePage.tsx` — "В корзину" в персональных рекомендациях
- `passport/CoffeePassportPage.tsx` — "Перейти в каталог" (была `bg-gold`)

Вторичные (outline) CTA унифицированы отдельным, но тоже единым языком: `border-border text-burgundy hover:border-accent hover:bg-accent-surface` — применено к "Не знаю, что выбрать" (Hero), "Подобрать кофе" (Catalog), "Мой кофе"/"Паспорт"-ссылкам на разных страницах. Раньше эти кнопки при ховере заливались золотом (`hover:bg-gold hover:text-burgundy`) — теперь ховер даёт лёгкий burgundy-тинт (`accent-surface`), не золотую заливку.

Селекторы состояния (не купить, а выбрать: способ оплаты, метод заваривания, рейтинг 1–5, выбор лота для дегустации, Discovery-опции, табы каталога) тоже переведены на единый `accent`/`tab-active` язык вместо смешанного `border-gold`/`bg-burgundy`, чтобы "выбрано" во всём приложении означало один и тот же визуальный сигнал.

**Gold как CTA-заливка не остался нигде** — проверено `grep -rn "bg-gold\b" src/` (раздел 11): все 7 оставшихся мест — прогресс-бар бесплатной доставки, "Точка входа"-бейдж, декоративная линия под эйбраузом Hero, счётчик корзины в шапке, flying-dot анимация — то есть ровно микро-акценты, не CTA.

## 6. FixedBackdrop

Подтверждено (унаследовано из прерванной сессии, не переделывалось): компонент **удалён полностью** — и вызов в `app/layout.tsx`, и сам файл `src/components/FixedBackdrop.tsx`. Не заменён новым узором/текстурой — согласно прямому указанию задания ("не создавать вместо него новый сложный декоративный паттерн"). Фон документа теперь — просто `var(--color-background)` (cream), без градиента и без иллюстрации кофейных веток/зёрен.

Прямое следствие: каждая секция, которая раньше была полупрозрачной "стеклянной панелью" (`bg-backdrop/35`, `bg-cream/85`, `backdrop-blur`) поверх этого узора, в этой сессии переведена на **непрозрачную** заливку (`bg-surface` для светлых, `bg-surface-accent` для намеренно тёмных) — иначе полупрозрачность поверх пустого cream-фона выглядела бы блёкло, а не как задумано изначально поверх тёмного узора. Это затронуло: `Hero`, `Approach`, `Catalog`, `Manifest`, `Footer`, `CoffeePassportPage`, `CoffeePassportDetail` (вложенная секция), `MyCoffeePage`.

## 7. Product cards — визуальная декомпрессия

Не архитектура карточки, а именно декомпрессия, как просило задание. Изменения в `Catalog.tsx`:

- Убраны отдельные "боксы" вокруг метаданных, которые не несут промо-смысла: лейбл лота и бейдж "Паспорт" стали простым текстом без рамки/фона (было — обе в рамках); Q-score перешёл с `border-gold/40 bg-cream` на нейтральный `border-border` — тем самым в карточке остался только **один** по-настоящему золотой элемент — бейдж "Точка входа" (легитимный промо-маркер, сохранён как есть).
- Три отдельные строки-метаданные — рекомендация по завариванию, происхождение/сорт/обработка, "только цельное зерно" — **объединены в одну** приглушённую строку через " · ". Информация не удалена (что явно запрещало задание) — она осталась вся, просто перестала занимать три визуальные строки подряд.
- Бордер карточки — с `border-gold/30` на `border-border`; hover — с `hover:border-gold` на `hover:border-accent/40`.
- Итоговая иерархия карточки (сверху вниз): лейбл/паспорт (текст, без рамки) → страна+регион+Q-score → промо-бейдж (если есть) → характер вкуса (если есть) → cup note (главный вкусовой акцент, `line-clamp-2`, было `-3`) → "кому понравится" (визуально on notch тише) → одна строка метаданных → цена + CTA. Не 9 конкурирующих элементов, но и не переписанная с нуля архитектура.

Тот же принцип (нейтральный дефолтный бордер, gold только для по-настоящему уникального маркера) применён и в `LotPassportModal.tsx`, `passport/MyCoffeePage.tsx`.

## 8. Semantic colors — success/warning/error

- **Error:** единственный найденный hardcoded статус-цвет — `text-red-700` в `CheckoutForm.tsx` (валидационная ошибка поля) — заменён на `text-error`. Значение не изменилось (`#b91c1c` формализует то же самое, что уже отображалось), поэтому визуально ничего не "сломалось" — просто у цвета появилось имя и единый источник.
- **Success:** иконка подтверждения заказа в `cart/OrderSuccess.tsx` (`border-gold text-gold` — единственное на весь сайт место, где gold использовался как индикатор состояния, а не акцент) переведена на `border-success text-success`. Это единственное найденное место, где семантически "success" был замаскирован под "premium accent" — теперь у него собственный, отдельный от gold, цвет.
- **Warning:** токен добавлен и задокументирован, но **не применён нигде** — в текущем UI не нашлось ни одного существующего предупреждающего состояния, которое стоило бы перекрашивать без изобретения нового UI-элемента (что было прямо запрещено). Зафиксировано как готовый, но пока неиспользуемый токен.

Никакого масштабного рефакторинга ради этого не потребовалось — заменена одна строка (`text-red-700` → `text-error`) и один компонент (`OrderSuccess` иконка).

## 9. Coffee Passport — визуальное приведение к системе

Не менялась ни одна функция/структура данных `src/lib/coffeePassport.ts`, `src/types/coffeePassport.ts` — только цвет/фон трёх компонентов, которые рендерят локальный дегустационный журнал:

- `passport/CoffeePassportPage.tsx` — главная тёмная панель (`bg-backdrop/35`) → светлая (`bg-surface`); "not found" панель — туда же; таб-селектор лотов заказа переведён с dark-context стилей (`border-white/15 bg-white/15 text-cream/80`) на light-context (`border-border bg-cream-dark text-text/70`) — это была одна из главных находок аудита: тёмная страница со стилями, скопированными "как есть" из тёмной секции каталога, при переходе каталога на светлую тему выглядела бы "осиротевшей".
- `passport/CoffeePassportDetail.tsx` — уже был в основном светлым (эта секция всегда рендерилась вложенной в `bg-cream` блок), доработаны только: рейтинговые кнопки 1–5 (`border-gold bg-gold` → `border-accent bg-accent`), селекторы метода заваривания/характера (убрана избыточная `border-gold` рамка поверх и так burgundy-заливки), два бордера с `border-gold/*` на `border-border`.
- `passport/MyCoffeePage.tsx` — тот же перевод, что и `CoffeePassportPage`: главная панель, карточки "лоты, которые вы пробовали" и "последние дегустации" (были `border-white/15 bg-white/10 text-cream/*`, стали `border-border bg-cream-dark/60 text-text/*`).

Результат — Coffee Passport теперь визуально неотличим по языку от остального сайта (тот же surface/border/accent словарь), не "отдельная SaaS-панель", ровно как требовало задание. Функциональность (localStorage-хранение, резолв лотов, рейтинги, история) не тронута ни строкой.

## 15. Визуальная проверка

**Честное ограничение сессии:** попытка открыть живой dev-сервер (`npm run dev`, поднялся успешно на `localhost:3000`) в браузере через доступный browser-automation инструмент не удалась — расширение Chrome для этой интеграции не подключено в текущей среде (`tabs_context_mcp` вернул "Browser extension is not connected"). Скриншот/живой визуальный осмотр в этой сессии физически невозможен — это ограничение окружения, не пропущенный шаг.

Вместо этого выполнена исчерпывающая **статическая проверка кода**, эквивалентная ручному code review каждого изменённого файла:
